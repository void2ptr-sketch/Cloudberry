# Домен Cloudberry

## Назначение

**Cloudberry** — облачное приложение учёта **для облаков** (cloud accounting for clouds).

Система помогает компаниям видеть, понимать и контролировать финансы, связанные с использованием публичных и частных облаков: расходы по провайдерам, проектам, командам и окружениям (prod / staging / dev).

Cloudberry не заменяет бухгалтерскую ERP целиком, а закрывает узкий, но критичный слой — **учёт и аналитика облачных затрат** (FinOps / cloud financial management).

## Проблема

- Счета приходят из нескольких облаков (AWS, Azure, GCP, Yandex Cloud и др.) в разных форматах.
- Сложно сопоставить затраты с продуктами, командами и бюджетами.
- Не очевидны всплески расходов и не используемые ресурсы.
- Финансовый и инженерный контуры говорят на разных языках.

## Ценность для пользователя

| Роль | Что получает |
| --- | --- |
| FinOps / платформенная команда | единая картина расходов, алерты по бюджетам, разбор по тегам |
| Руководитель / CFO | отчёты по периодам, прогноз, сравнение план/факт |
| Инженер / тимлид | затраты своей команды и сервисов без доступа к «чужим» данным |
| Бухгалтерия | выгрузки и сверка с внутренними статьями учёта |

## Основные понятия (bounded context)

### Облако и подключение

- **Cloud provider** — поставщик (AWS, Azure, GCP, …).
- **Cloud connection** — привязка аккаунта/подписки (credentials, billing export, CUR).
- **Scope** — граница данных: организация, billing account, subscription.

### Учёт затрат

- **Usage line** — строка потребления (сервис, регион, SKU, количество, цена).
- **Cost record** — нормализованная запись расхода в единой модели (валюта, дата, сумма).
- **Allocation** — отнесение затраты на **cost center** (проект, команда, продукт) по правилам или тегам.
- **Amortization** — распределение резервирований, скидок и committed use по периодам.

### Планирование и контроль

- **Budget** — лимит на период (месяц/квартал) для scope или cost center.
- **Alert** — срабатывание при превышении порога или аномалии.
- **Forecast** — оценка расхода до конца периода на основе тренда.

### Отчётность

- **Report** — сводка за период (по провайдеру, тегам, сервисам).
- **Dashboard** — оперативные виджеты (топ сервисов, динамика, burn rate).

## Границы системы

**В зоне ответственности Cloudberry:**

- импорт и нормализация billing-данных из облаков;
- дашборды, отчёты, бюджеты и алерты;
- распределение затрат (showback / chargeback);
- роли и доступ к финансовым срезам.

**Вне зоны (интеграции, не ядро MVP):**

- полный бухгалтерский учёт (проводки, НДС, закрытие периода) — через экспорт в ERP;
- управление инфраструктурой (создание VM, Kubernetes) — только чтение метаданных для контекста;
- платёжные операции — Cloudberry не списывает деньги с карт.

## MVP (первая версия продукта)

1. Подключение одного провайдера (или загрузка CSV billing export).
2. Дашборд: расход за месяц, топ-5 сервисов, сравнение с прошлым месяцем.
3. Простой бюджет на организацию + уведомление при 80% / 100%.
4. Таблица детализации с фильтром по периоду и тегу `Environment`.

## Дорожная карта (после MVP)

- Несколько провайдеров в одном tenant.
- Правила allocation (по тегам, namespace, account map).
- Прогноз и рекомендации по оптимизации (idle resources, rightsizing hints).
- SSO, audit log, мультивалютность.
- API и webhooks для ERP / Slack.

## Термины на английском (для кода и API)

| RU | EN (предпочтительно в коде) |
| --- | --- |
| подключение к облаку | `CloudConnection` |
| запись расхода | `CostRecord` |
| центр затрат | `CostCenter` |
| бюджет | `Budget` |
| отчёт | `Report` |
| провайдер | `CloudProvider` |

## Принципы моделирования

- Все суммы хранятся с **валютой** и **датой начисления** (accrual date), не только датой счёта.
- Идентификаторы провайдера не смешиваются: у каждого connection свой внешний ключ.
- Пользователь видит только те scope и cost center, на которые у него есть право.
- UI и API опираются на одну доменную модель; дублирования сущностей в фичах избегаем.

## Связь с кодовой базой

Доменные типы и константы — в `src/app/core/domain/`.  
Фичи в `src/app/features/` отражают пользовательские сценарии (dashboard, budgets, connections, reports).

### Маршруты (MVP)

| Путь | Фича |
| --- | --- |
| `/dashboard` | дашборд (главная после редиректа с `/`) |
| `/connections` | подключения к облакам |
| `/budgets` | бюджеты и алерты |
| `/reports` | отчёты |
| `/costs` | детализация расходов |

Сегменты путей — в `src/app/core/routing/app-route-paths.ts`.
